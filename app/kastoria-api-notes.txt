KASTORIA CITYBUS - DATA API NOTES
=================================
Mapped on 2026-10-12 (Monday) from https://kastoria.citybus.gr/el/stops
(watched in Claude's built-in browser, plus reading the site's own /js/stops.js)

-------------------------------------------------------------------------------
0. GENERAL
-------------------------------------------------------------------------------
Base URL ..........: https://rest.citybus.gr
Agency code .......: 115   (= Kastoria; other cities on citybus.gr use other codes)
Language segment ..: el | en   (most endpoints have it, /lines/{lineCode}/points does NOT)
All calls .........: GET, JSON (application/json; charset=utf-8)

Headers the site sends on every API call:
  Authorization: Bearer REDACTED
  Accept: application/json, text/javascript, */*; q=0.01
  Content-Type: application/json; charset=utf-8

Without the Authorization header the API answers 401 (empty body).

Site pages: the website itself only has ONE real page: /el/stops (and /en/stops).
/, /el, /el/lines, /el/map, /el/routes, /el/live, /el/vehicles, robots.txt and
sitemap.xml all return 404. "Lines", "routes" and "map" are all part of the
stops page (map + filters), so every endpoint below comes from that one page.

Page config (inline <script> in the HTML of /el/stops):
  const agencyCode = 115;
  const apiUrl = 'https://rest.citybus.gr';
  const token = 'REDACTED';
  const language = 'el';
  const maxLiveDepartureMinutes = 30;      // live tab shows buses due in next 30 min
  const latSW = 40.440979;  const lngSW = 21.041117;   // map bounds (south-west)
  const latNE = 40.580043;  const lngNE = 21.363929;   // map bounds (north-east)
  repeatInterval = 20  (in stops.js)       // live data refreshes every 20 s

Identifier note: URLs use the stop CODE (e.g. "16044"), the route CODE
(e.g. "001") and the line CODE (e.g. "01") - all strings. The numeric "id"
fields are internal database ids and are not used in any URL.

-------------------------------------------------------------------------------
1. WHERE THE BEARER TOKEN COMES FROM
-------------------------------------------------------------------------------
Request ...: GET https://kastoria.citybus.gr/el/stops   (or /en/stops) - the HTML page itself
There is NO separate login/token API call. The server writes the token directly
into the HTML as a JavaScript constant:   const token = '<JWT>';
stops.js then sends it as "Authorization: Bearer <token>" on every API call.

Token format: JWT, header {"alg":"HS256","typ":"JWT"}, payload contains ONLY
"exp" (no user, no iat, no scope).

Lifetime: ~48 hours.
  - Page loaded 2026-10-12 09:00:47Z  -> exp 2026-10-14 09:00:47Z  (exactly +48 h)
  - Another load at ~08:53Z had exp 08:43Z+48h, so the HTML seems to be cached
    for a few minutes; the token can be up to ~10-15 min "older" than the page load.

For the app: download /el/stops HTML, regex  const token = '([^']+)'  , decode the
JWT payload to read "exp", and refresh (re-download the page) before it expires
or whenever an API call returns 401.

2. ALL STOPS  (names, codes, coordinates)
-------------------------------------------------------------------------------
GET https://rest.citybus.gr/api/v1/{lang}/{agencyCode}/stops
    e.g. https://rest.citybus.gr/api/v1/el/115/stops
Headers: Authorization: Bearer REDACTED
Returns: an array with every stop of the agency (209 stops for Kastoria), with
coordinates and which lines/routes serve it. ~45 KB. Called once on page load.

    e.g. https://rest.citybus.gr/api/v1/el/115/lines

Returns: an array of all lines, each with its colours and the list of routes

5. ROUTE SHAPES (polylines) OF A LINE
-------------------------------------------------------------------------------
GET https://rest.citybus.gr/api/v1/{agencyCode}/lines/{lineCode}/points
    e.g. https://rest.citybus.gr/api/v1/115/lines/01/points

Headers: Authorization: Bearer REDACTED

6. LIVE ARRIVALS FOR A STOP  (+ LIVE BUS POSITIONS)
-------------------------------------------------------------------------------
GET https://rest.citybus.gr/api/v1/{lang}/{agencyCode}/stops/live/{stopCode}
    e.g. https://rest.citybus.gr/api/v1/el/115/stops/live/16044
Headers: Authorization: Bearer REDACTED
Returns: the buses expected at this stop in the next 30 minutes, INCLUDING each
bus's current GPS position. Polled every 20 seconds while the "Τηλεματική" tab
is open. There is NO separate "all vehicles" endpoint - live bus positions only
come from this per-stop call.

When no bus is expected, the API answers HTTP 404 with this body (the site then
shows "Δεν αναμένονται δρομολόγια για τα επόμενα 30 λεπτά"):
  {"type":"https://tools.ietf.org/html/rfc7231#section-6.5.4","title":"Not Found",
   "status":404,"traceId":"00-...-...-00"}
=> In the app treat 404 here as "empty list", not as an error.

Response sample: NOT CAPTURED. During the whole session (Mon ~11:55-12:05 local)
every live call returned 404 - even at ΑΦΕΤΗΡΙΑ (16001) where the timetable had a
line 06 departure at 12:30. So probably no GPS-tracked bus was active, or buses
only appear once they are assigned/moving.

Response structure, as read from the site's stops.js (field names are certain,
exact types/units are my reading of the code):
  {
    "vehicles": [
      {
        "vehicleCode":      bus id (used to highlight the bus on map/list)
        "lineCode":         line code, e.g. "06"
        "routeCode":        route code, e.g. "006"
        "routeName":        route name
        "lineColor":        hex colour of the line badge
        "departureMins":    minutes until the bus reaches this stop
        "departureSeconds": seconds until arrival (used for the "blinking" when close)
        "latitude":         current bus latitude
        "longitude":        current bus longitude
        ... (stops.js also uses lineTextColor/borderColor from the vehicle or line)
      }
    ]
  }
The site draws each vehicle marker at (latitude, longitude) and the route
polyline of its routeCode (from /lines/{lineCode}/points).

7. TIMETABLE FOR A STOP ON A DAY
-------------------------------------------------------------------------------
GET https://rest.citybus.gr/api/v1/{lang}/{agencyCode}/trips/stop/{stopCode}/day/{day}
    e.g. https://rest.citybus.gr/api/v1/el/115/trips/stop/16044/day/1
Headers: Authorization: Bearer REDACTED
{day}: 0 = Sunday (ΚΥ), 1 = Monday (ΔΕ), 2 = Tuesday (ΤΡ), 3 = Wednesday (ΤΕ),
       4 = Thursday (ΠΕ), 5 = Friday (ΠΑ), 6 = Saturday (ΣΑ)
       (same numbering as JavaScript Date.getDay(); tested 1, 6 and 0)
Returns: every scheduled pass of any line/route through this stop on that day,
sorted by time. Called when a stop is selected (today) and on each day tab click
in "Πρόγραμμα".

8. "GetViewportInfo"  -  NOT part of the bus API
-------------------------------------------------------------------------------
POST https://maps.googleapis.com/$rpc/google.internal.maps.mapsjs.v1.MapsJsInternalService/GetViewportInfo
This is an internal call of the Google Maps JavaScript API itself (not of
citybus.gr). Google Maps sends it whenever the visible map area changes, to get
metadata for that viewport: map-data copyright/attribution text ("©2026 Δεδομένα
χάρτη Google"), available zoom levels / imagery info for the area, etc.
It contains no bus data - ignore it. Your Android app will use its own map SDK.

Other non-API domains the page talks to (all ignorable):
  maps.googleapis.com (map tiles, /maps/api/js), fonts.googleapis.com,
  googletagmanager.com + region1.google-analytics.com (Google Analytics G-G2YWEZFP74)

9. SUGGESTED APP FLOW
-------------------------------------------------------------------------------
 1. GET /el/stops HTML -> extract token (cache until exp, refresh on 401).
 2. GET /api/v1/el/115/stops and /api/v1/el/115/lines once, cache locally
    (they rarely change).
 3. Route shapes: /api/v1/115/lines/{lineCode}/points - only for the line the
    user opens; cache.
 4. Stop screen: /trips/stop/{stopCode}/day/{0-6} for the timetable;
    /stops/live/{stopCode} every 20-30 s for live (404 = no buses).
 5. Route screen: /routes/{routeCode}/sequence + join codes with the stops list.
